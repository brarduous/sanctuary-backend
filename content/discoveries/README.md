## What changed

The original 36 questions were assistant-authored starters. They were not output from a running cron and had no live two-model approval. They are preserved in `retired/biblical-starter-assistant-v1.json` and are no longer the default import or preview bank. Their previous synthetic UI approvals never represented production editorial decisions.

The contextual pilot uses the same model adapters and acceptance functions as the curriculum cron. The standalone v3 pilot generated files only. The October 28 release rehearsal subsequently installed the schema in the isolated `discovery-release-20261028` preview branch and exercised the actual cron there, including SQL auto-approval and persistent exhaustion. Production publication remains gated; see the rollout record.

The seven-scene v3 trial produced five passing model drafts, one exhausted candidate, and one candidate stopped by the run budget. Two model-passing drafts were additionally held by the assistant for potentially overlapping answer categories; see `editorial-dispositions.json`. Those two are excluded from the default bank. The earlier simple Lazarus-name and face-covering revisions were also held, with their failed rechecks retained. No rejection was silently changed to an approval.

Earlier experiments under `experiments/` and the v2 pilot preserve the prompt/protocol failures that led to explicit verdict-confidence semantics, trusted verse selections, bounded JSON-schema verse IDs and separate craft/context checks. They are not release content. Recorded token usage includes completed calls for which usage was returned; failed or interrupted provider calls can have unavailable usage.

The shared canonical verse extractor removes markup, decodes entities and collapses whitespace exactly as the trusted corpus builder does. It never changes wording. This resolved an app/corpus mismatch caused by a double space in Mark 10:52 while retaining exact canonical-text and SHA-256 checks.

## Commands

```sh
npm run validate:discoveries
npm run review:discoveries
node scripts/discoveries/importCandidates.js  # validates only; no --apply
npm run test:discoveries

# Inspect the reviewed source/angle plan without API calls or database writes.
npm run draft:discoveries -- --plan content/discoveries/contextual-pilot-plan.json

# Requires OPENAI_API_KEY. Uses real writer/review calls, writes only draft/audit files.
npm run draft:discoveries -- --live --plan content/discoveries/contextual-pilot-plan.json --count 7 --output content/discoveries/new-pilot.json

# Recheck an unchanged earlier draft against the current gate, without publishing.
node scripts/discoveries/recheckDraft.js --live --input content/discoveries/drafts.json --slug example-slug --output content/discoveries/rechecked.json
```

The offline runner enforces three attempts per candidate, resumable audits, prompt/model/plan hashes, and a bounded run budget. Resuming never resets an exhausted candidate or regenerates an accepted one. Production DB leases and scheduling remain in the existing cron implementation. See `docs/DAILY_DISCOVERY_CURRICULUM.md` for the policy and calibration requirements, and `docs/PRODUCTION_DATABASE_ROLLOUT.md` for hosted rollout prerequisites.

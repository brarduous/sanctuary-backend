# Mobile daily loop compatibility release

Targets: Sanctuary production Supabase `cmakuvkjxknwhonfqbit`, Render `srv-d1uqipvdiees73b0kj20`, mobile 1.2.13, and the existing layperson web project. Preserve unrelated dirty checkouts; implementation uses a worktree based on current origin/main.

The reading-time migration expands validation to 40 seconds while accepting old 20-second timeouts. It guards the exact existing completion function before replacing its timing conditions. The metrics migration adds optional attribution/pseudonymous cohort columns and intentionally changes Trivia's time to 19:00. It changes neither consent nor category activation. Existing clients may continue sending their old metrics. No completion history is backfilled or rewritten.

`daily-participation-v1` counts three distinct canonical daily question IDs in positions 1–3, any answer/reveal/timeout. An incomplete today preserves yesterday's continuing streak. Archive play is excluded. Delivery aliases retain original dates and supply a separate validated daily play date for carried sets. The older perfect-set calculation remains separate. Account sync now retrieves all history instead of truncating to 200 rows.

Reminders reuse the existing calendar/15-minute dispatcher, quiet hours, six-hour spacing, and per-user/local-day deduplication. Only explicitly opted-in signed-in native daily-set clients (capability version 2, bound to current token) qualify. Missing/withdrawn/incomplete sets skip. Three completions suppress regardless of score. Unsynced offline play remains unknown to the server. `/discoveries?source=push` opens the overview, without auto-starting a timed question.

Metrics accept optional Home/Games/shared-link/push attribution, session IDs, set date, and an existing installation ID. A server-only `DISCOVERY_METRICS_SALT` HMAC turns account/installation identity into a nonreversible cohort key; raw identity is not stored in metrics. Missing salt omits cohort identity instead of storing it raw. Share initiation measures sheet/copy intent only. Historical mount impressions cannot be compared directly with new viewport impressions. Aggregate reporting is in `scripts/discoveries/mobileLoopReport.sql`; UTC activity cohorts need full one/seven-day windows. Account/guest identities are separate and cannot establish person-level retention across sign-in.

Validation: 257 existing backend tests passed, plus three new participation/copy/metric tests. Isolated PostgreSQL integration exercises consent, version/token mismatch, partial versus all-three completion including reveals/timeouts, withdrawal, time zone, quiet hours, audience pagination, native routing, and duplicate sends. No live accounts, pushes, or payments were used. Hosted staging currently has no Discovery schema, so this release's schema rehearsal is isolated PostgreSQL, not hosted staging. Production completion function and PITR metadata were captured privately before migration; an actual recovery restore was not performed.

Operational baseline November 2: Trivia enabled at 100%; discovery reminders disabled/dry_run at 18:00; zero Trivia opt-ins and zero delivery records. Preserve disabled state through release. A real internal opted-in cohort and receipt/tap evidence must precede 10% → 50% → 100% rollout. Rollback pauses discovery notifications and retains compatible data. The two-week usage review and conditional expansion remain future work.

The existing Stripe `/webhook` still treats payment-mode Checkout as a subscription. Giving remains unverified; do not label a mocked event or source audit a completed sandbox donation. No financial code is changed in this daily-loop release.
